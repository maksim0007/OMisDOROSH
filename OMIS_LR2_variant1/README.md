# ОМИС — Лабораторная работа № 2, вариант № 1

**Тема:** Реализация объектной модели автоматизированной системы учёта и анализа клиентского опыта и отзывов.

## Как запустить

1. Установите **Python 3.10 или новее** (Windows / Linux / macOS с Tkinter).
2. Откройте папку с проектом в VS Code или терминале.
3. Запустите `python main.py` (в Windows также `py main.py` или двойной щелчок по `run.bat`).
4. Необязательно: перед запуском выполните `python seed_demo.py`, чтобы заполнить аналитику и список отзывов шестью демонстрационными записями. Повторный запуск скрипта не создаёт дубликаты.

Внешние библиотеки не требуются: `tkinter`, `sqlite3` и остальные модули входят в стандартную библиотеку Python. Данные сохраняются автоматически в `feedback.db` рядом с исходниками.

## Демо-доступ

| Логин | Пароль | Роль | Экран |
|---|---|---|---|
| `client` | `demo123` | Клиент | Отправка отзыва |
| `manager` | `demo123` | Менеджер | Обработка отзывов |
| `analyst` | `demo123` | Аналитик | Дашборд |
| `admin` | `demo123` | Администратор | Управление пользователями |

**Проверка сценария:** зайдите как `client`, добавьте отзыв, выйдите, зайдите как `manager`, возьмите отзыв в работу и смените статус на «Решен», затем как `analyst` откройте статистику. Все переходы выполнены внутри работающего приложения.

## Структура

- `model.py` — `Client`, `Product`, `Rating`, `Status`, `Feedback`.
- `services.py` — `FeedbackRepository`, `AuthService`, `SentimentAnalyzer`, `FeedbackService`, `FeedbackController`, `AnalyticsService`, `AdminService`.
- `ui.py` — `LoginWindow`, `FeedbackFormWindow`, `SupportWindow`, `DashboardWindow`, `AdminWindow`.
- `main.py` — `App`, `AppInjector`, запуск.
- `tests/test_services.py` — автоматические проверки.
- `seed_demo.py` — добавление шести примеров отзывов в пустую базу.
- `run.bat` — запуск на Windows.
- `BUGS.md` — экспертный список ошибок и расхождений модели ЛР № 1.
- `screenshots/` — зафиксированные окна программы.

## Тесты

Из папки проекта: `python -m unittest discover -s tests -v`.

## Архитектура

`UI → FeedbackController / Services → FeedbackRepository → SQLite`.

Модель следует классам из ЛР № 1. Предлагаемые в ЛР № 1 направления **будущего развития** (Telegram/VK/WhatsApp, предиктивная аналитика, геймификация) намеренно не включены в базовую реализацию, поскольку они представлены на **отдельных диаграммах расширения**, а не на базовой диаграмме.

## Ограничения учебного прототипа

- Вместо указанной в рекомендациях ЛР № 1 PostgreSQL использована SQLite для запуска без сервера. При этом класс `FeedbackRepository` скрывает способ хранения данных.
- `SentimentAnalyzer` использует демонстрационный словарный алгоритм; это не промышленная NLP-модель.
- В модели описаны SLA, эскалация и подтверждение решения клиентом, но подробной логики эскалации в прототипе нет. Повторное открытие реализовано изменением статуса «Решен» → «В работе».
- Тема «противодействие спаму» и внешние интеграции представлены проектной моделью, но не программной реализацией.
- Тестовые учётные записи и пароль предназначены только для демонстрации; не использовать для реального сервиса.

```bash

git add .
git commit -m "Implement OMIS lab 2 variant 1"
git branch -M main

git push -u origin main
```

Замените `USERNAME` на свой GitHub-логин. В отчёте поле **«Ссылка на исходный код»** оставлено для URL репозитория: фактическая публикация не выполнялась. Для Windows PowerShell команды совпадают.
